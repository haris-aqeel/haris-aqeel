## 🔁 How I Build: The Agentic SDLC

I run my own delivery with **AI-driven development workflows**, not just autocomplete.

### BMAD-style agile AI-driven development

Specialized agent personas (**Analyst → PM → Architect → Scrum Master → Dev → QA**) hand work to each other through **versioned artifacts**, not chat history:

```
Brief → PRD → Architecture → Sharded Epics → Story Files → Implementation → QA Gate
```

- **Spec-driven development**: SRS, EARS-style "shall" requirements, use cases, and a traceability matrix come *before* code
- **Story files as context**: each story carries the exact context, acceptance criteria, and tasks an implementing agent needs
- **Independent verification**: a separate agent audits tests against acceptance criteria, so no agent grades its own homework
- **Amendment paths**: when reality diverges from the design, the agent escalates instead of quietly redesigning
- **Stable IDs end to end**: requirement → use case → feature → test, so nothing ships untraced

### Claude Code-native workflows

- **Subagents** for parallel, scoped work (research, review, implementation)
- **Skills** that encode repeatable playbooks for design, build, and verification
- **Hooks** for guardrails: lint, test, and policy checks around every tool call
- **MCP servers** to connect agents to project trackers, docs, chat, hosting, and databases
- **Headless / VPS agents** triggered from chat, e.g. a message goes to an orchestrator agent, which drives Claude Code, which deploys a finished site
